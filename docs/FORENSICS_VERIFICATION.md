## Limits and outstanding acceptance

- Production `/api/account` reports `configured: false`; Google and GitHub are unavailable until the database, Auth.js secret and provider credentials/callbacks are configured. Live OAuth and hosted database connectivity were not tested. Private CRUD was verified with actual SQL/Auth.js against test infrastructure, not a configured production account.
- No authorized tester supplied a genuinely unfamiliar conversation. The requested final manual acceptance against such a source is still outstanding. Generated exports/screenshots and real model calls verify integration behavior, not scam-detection accuracy.
- Retry coalescing is bounded to the mounted page and one server instance for five minutes. Cross-instance exactly-once billing requires shared durable storage. There is no global model-spending cap.
- One constrained public mobile lab run measured LCP **6,572 ms**, CLS **0.00037**, 305,470 transferred bytes and no WebGL load. Conditions: 390×844, cache disabled, 150 ms latency, 1.6 Mbps, 4× CPU, reduced motion. Layout stability was strong; LCP missed the 2.5-second target and remains performance work. This is a single lab observation, not field data.
- No human screen-reader study, broad regional WhatsApp-format validation or forensic accuracy benchmark was conducted. OCR, speaker labels, user edits, selection omissions and model interpretation can be wrong. Selection and uncertainty notes are visible in the UI and exports.
